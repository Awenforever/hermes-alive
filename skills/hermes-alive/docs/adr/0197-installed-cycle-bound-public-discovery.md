# ADR0197 — Public discovery inside the installed owner-bound cycle

Status: implemented vertical slice; final qualification and real quality pending

## Missing capability and decision

The installed shadow host could analyze retained material but did not acquire
new public observations. Private experiments manually fetched and seeded them.
Successful component tests therefore did not prove an autonomous installed path.

Reuse CoreDiscoveryTools, HostDiscoveryReader, the encrypted agenda and existing
native host/cognition/expression/final-assessment loop. A separately consented
preparation runs AFTER durable cycle identity and current profile/policy/model
binding exist. It cannot run as an unbound startup parameter callback. Paused
owner policy bypasses preparation and completes as paused without IO.

The opt-in setup accepts one to three explicitly approved public queries and a
separate confirmation. Model-call consent is not disclosure consent. No queries
are invented from private memories, copied from the owner's production profile,
or made public defaults. Users express public scope naturally; Hermes converts
confirmed choices into setup arguments. Core owns actual search availability,
URL/DNS safety, provider configuration and model primary/fallback selection.

The existing reader collects bounded listings. A single current Core model call
chooses at most two supplied references to read or abstains, with a tentative
research question/value hypothesis. The exact query scope, original search
receipt, prompt digest, context revision, source snapshot, actual model and
choice are bound to durable encrypted history before/after spending. That is
research intent, never a user preference, a fact or delivery permission.
Original page reads go through the existing reader and its physical lease.
Their evidence/inquiry then feeds the installed cognition and actual final
source/value checkpoint. ADR0196 keeps internal tasks out of recipient writing.

## Failure, lifetime and recovery

Configuration/model/public consent, owner policy, profile, context revision and
original source availability remain current across awaits. A changed/forgotten
owner context, erased source, invented reference or withdrawn consent cannot
admit a reading choice. Exact completed operations replay without model or web
IO. Incomplete/failed selection or physical reads require reconciliation, not a
new spend under the same operation. A failure does not close the host cycle as
success, forge source freshness or silently declare a delivered message.

Native host pending/reaping now includes the preparation's actual physical read.
Timeout/cancellation cannot start another cycle while it remains pending; a
reloaded instance also encounters the reader's incomplete receipt and existing
Core read file lock. New code does not create another scheduler, transport queue,
provider client, memory store or sending capability. Default installs, legacy
engine and model-only shadow consent retain their previous behavior.

Real installed trials exposed two additional limits before any model call:
the isolated model-only profile did not inherit the NAS proxy/search environment,
and the old60s total host read cap retired a still-running Core operation. Core's
extract dispatch alone defaults to120s plus its own recovery. The independent
host stage now defaults180s (explicit finite overrides capped600s), without
changing Core provider/request timeouts, URL safety, retries or rescue routing.
Tests must supply working network prerequisites; this is not a promise that a
proxy fixes all backend failures or that a longer wait establishes useful output.

The host now records authenticated failure phase/class/cause-class in its
existing event history, and returns the failure class rather than only the
undifferentiated cycle_failed label. It records no exception message/traceback or
query/credential-bearing content in plaintext. Failure is not completion, a
closed cycle or an automatic retry grant. Unknown physical reads still require
settlement/reconciliation; persistent failure recovery remains an acceptance gap.

## Evidence and remaining scope

Focused controlled integration exercised the actual encrypted native host ->
public reader -> internal inquiry -> planning -> expression -> final assessment
path and no-inference/no-IO recovery after an interruption before host close.
Negative paths cover failed page extraction, abstention, pause, unknown source
references, consent withdrawal, owner-memory forgetting, source erasure and a
physically pending read. Qualification must use terminal results, not intent.

A pinned actual Core probe also starts with no pre-seeded source, configures via
the real plugin CLI, installs the actual gateway hook, starts via HookRegistry,
dispatches controlled tools through Core's registry and exercises six actual
SDK-admitted model stages through the plugin facade. Sources, HTTP/model and
URL-safety answers are synthetic; no real model quality or URL-security claim.
Reinstall must preserve disclosure configuration and history. Existing generic403,
API-shape and declared dependency limitations are not claimed fixed here.

This is a bounded installed discovery vertical slice, not the completed Alive.
Next qualify exact bytes and fresh public/model outcomes through that installed
path. Still open: richer sustained inquiry across cycles, noisy/external memory
and Halo/erasure, source variety and China accessibility, user knowledge/novelty,
actual useful voice, outcomes/reflection/feedback, migration/platforms, ten fresh
complete clean rounds and production acceptance. No deployment or live send.
