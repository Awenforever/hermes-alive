# ADR 0147 — User-admitted commitments enter current cognition

Date: 2026-10-16. Status: isolated integration, incomplete expression quality;
not deployed, not production acceptance.

## Problem and decision

Alive must remain useful without a stream of external discoveries. An admitted
commitment is a source of current purpose, not a web observation, completed work,
permission to execute a task, or a reason to fabricate a link. Use a bounded
`CognitionOpportunityReader` to present discoveries and admitted commitments to
the same opportunity interpretation/selection/expression pipeline. Do not build
another scheduler or platform queue. Enhance remains Qoder's transport ownership.

The reader uses the established typed `AgendaProjection` content vault for
commitments. Discovery/model bundles keep their existing independent vault. Do
not search neighboring vaults or silently migrate content. Current selected
generated commitment candidates use that typed agenda in send authorization;
legacy manually authored candidates retain their existing explicit vault behavior.
Owner/item filters now precede agenda content access in authorization.

## Provenance, currentness and idle behavior

- Check canonical original proposal metadata, owner, sensitivity, content binding,
  user-source chain and the bounded legal transition history before resolving body.
  Model-proposed commitments need later explicit owner adoption. Completed,
  unavailable, expired, foreign or unadmitted commitments do not become material.
- Preserve whole commitment details, state, availability and due/expiry times.
  An oversized item is omitted whole, not cut so a condition or negation disappears.
  This is representable material, not a certificate that no obligations exist.
- Discovery and commitment context share a bounded view. Reserve some slots for
  commitments when discoveries exist; this is capacity allocation, not a substitute
  for model relevance decisions or proof of starvation-free long-term traversal.
- Bind the current commitment snapshot into interpretation start/reopen checks.
  Completion or a changed commitment during model waiting invalidates prior work.
  A future deadline bounds interpretation freshness; after it passes, a fresh
  overdue interpretation is possible. The original task is not silently deleted.
- No qualified current material produces an explicit, auditable system no-material
  completion without provider access. Reopen verifies its provenance and rejects
  it if new representable material appears. Do not call this a model judgement.
- Candidate bundles retain at most seven days and original evidence/feedback
  limits. This does not change retention of the original user agenda.

Delivered history now records the typed `agenda` dependency separately. Completion
invalidates a current reminder, not historical evidence that a message was sent.
Erasing the original commitment body makes its dependent history text unavailable.
This is availability enforcement, not complete physical erasure of every backup.

## Integration evidence and discovered defects

The composed synthetic fixture exercises no-material/no-spend and waiting,
commitment-only cognition, source support, selection/expression, explicit synthetic
route/delegation and send preparation; completion before/during inference; model
proposal adoption; delivered text dependencies/erasure and foreign-owner projection
tampering before content access. Its authenticated dispatch record is a fixture,
not real channel IO. Initial preparation exposed `agenda_content_unavailable` from
using the model vault instead of the typed agenda vault; the corrected path passes.

Windows initially failed temporary-directory cleanup because a fixture SQLite
connection was not closed. Use `contextlib.closing`, not just connection transaction
context. That failure remains a failure, not a passing logic result. The fixed
fresh fixture passes. Manual cleanup of the old synthetic directory
`C:\Users\king_\AppData\Local\Temp\alive-commitment-cognition-6atr7oyg`
was rejected by tool policy; do not bypass through another shell/tool. This is a
synthetic-data residue, not a production state or credential backup.

The retained Linux runner originally allowed a normal `SystemExit(0)` from one
test to stop the remaining suite. Its two printed markers were not eight-test
evidence. The private runner now handles only successful exit, propagates failures,
and reports each completed script plus the final exact suite count. Verification
here is current-module overlay over retained dependencies, not fresh installation
or complete portable CI. The corrected Linux run
`alive-commitment-regression-20261016-r3` terminates successfully with eight exact
script completions: commitment cognition, authorization, delivered history,
opportunity synthesis, feedback assimilation, semantic reconsideration, final
wording preparation and repair. Fresh Windows commitment cognition and legacy
authorization scripts also pass. No model calls or actual sends in these tests.

## Two actual model trials: quality remains unresolved

Terminal synthetic-only runs retain evidence under:

```text
/tmp/hermes-alive-installed-RJbQNAiD/model-only-commitments-20261016-r1/results/report.json
/tmp/hermes-alive-installed-RJbQNAiD/model-only-commitments-20261016-r2/results/report.json
```

Each run made five actual calls through the configured models. Empty-before,
completed-after and unadopted-model-proposal stages spent zero calls; the
commitment-only stage traversed interpretation, support, selection and expression.
No actual message was sent. Both jobs ended, temporary model exports were removed
and production start was unchanged during those jobs. Later Qoder deployments are
independent and must not be mistaken for a production baseline still unchanged.
Totals are now 187 logical calls / 200 observed async HTTP starts, failures included.

The first reminder recited internal constraints and used a relative countdown
liable to become wrong in a delayed queue. Scoped natural-expression guidance and
general asynchronous timing guidance improved the second to include an absolute
UTC deadline. It still recited what it would not do and said it was time already,
despite the future deadline. Both source/fidelity reviewers accepted these drafts.
Keep both failed-quality examples: they are not ten clean trials or utility proof.

This exposes an architectural distinction: factual support, immutable permission
and pragmatic usefulness are not the same judgement. The expression pipeline
protects the entire proposed draft as a `PROPOSED_CONTENT` atom, so unnecessary
guardrail recital becomes content fidelity is asked to preserve. Another phrase
replacement or a rule to hide all negations would destroy useful caveats. Next
qualify purpose-aware intent/meaning/expression: separate intended recipient value
from behavioral constraints, preserve material uncertainty and time semantics,
and permit model-driven natural wording without silently altering confirmed
content or treating a reviewer as action authorization. Maintain old evidence and
explicit versioned contracts rather than rewriting historical selected drafts.

## Outstanding obligations, not waived by this integration

1. Already queued transport is not automatically withdrawn on commitment
   completion. New preparation validation is not a recall of a handed-off bubble.
   Coordinate a trusted existing transport withdrawal contract with Qoder; do not
   read/write Enhance tables or create another FIFO.
2. Explicit custom commitment vaults are not threaded through the full host,
   authorizer and feedback interfaces. Default typed binding is not custom-vault
   migration/rollback qualification.
3. Metadata scan 128, transition bound 64, commitment view 32 and context view 8
   need coverage/attention reporting and sustained fair traversal. Oversized whole
   omissions must eventually be visible, not misrepresented as no obligations.
4. Typed agenda admission fixtures do not prove authenticated installed gateway
   ingress. Current work sends no email, performs no user task and marks no task
   completed autonomously.
5. Full physical forgetting, layered/external memory, version migration/rollback,
   longitudinal usefulness, installed lifecycle and production acceptance remain.
   Preserve the complete goal; neither a green suite nor a supported reminder
   completes it.
