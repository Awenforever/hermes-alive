# ADR 0151 — A source-only purpose stage does not by itself fix meaning

Date: 2026-10-16. Status: isolated paired diagnostic; do not add this stage to the
production/runtime loop on the strength of these observations.

## Distinguish the real architecture question from output order

ADR0150 only manipulated the requested order of visible JSON fields. The new
experiment actually separates interpretation from expression: the purpose path
receives original source/current owner context with **no draft, candidate goal or
output from the baseline path**. It returns a tentative now/defer/uncertain
decision, reason and v2 communication plan, never a draft or dimension scores.
Deferred/uncertain purposes carry no ready message plan and make no renderer call.

The comparator path uses the existing current candidate interpreter, constrained
to one contribution for this diagnostic. Both valid plans then use the same actual
renderer system contract, Chinese language option, exact literal/semantic-polarity
rules and host-bound canonical source link. Comparing a baseline raw draft against
a new-path rendered message would be unfair; here both are rendered. Presentation
is the same empty neutral fixture, not a real user's personality/style projection.

This is a practical paired architecture experiment, not a pure one-factor causal
test: role, contract complexity, scoring and call count differ. Alternating path
execution order and identical time-anchored source inputs reduce some confounds,
not all stochastic variation. One sample per cell and the implementing agent's
inspection are not independent, blinded or population-quality evidence.

Six fresh scenes cover an ordinary procurement-list nudge with no ordering
permission, explicitly requested no-format/no-delete assurance, an observatory's
group/booking conditions, an observational preliminary study, temporary meeting
silence and a polite-reply correction that applies only to today's minor updates.
No real user conversation or preference enters the fixture. Original data is
retained; none of these interpretations becomes an approved user fact or grant.

## Actual configured-model observation

`model-only-purpose-only-20261016-r1/results/report.json` under the retained
isolated root records **17 logical / 17 observed HTTP starts**. Five baseline
interpretations abstain; one reaches rendering. The purpose path communicates in
four scenes and defers in two, making ten calls versus the baseline's seven.
No source/purpose/fidelity model review, full policy/selection, send preparation,
actual channel, feedback or long-term adaptation is run. The renderer's structural
assessment stays REVIEW_REQUIRED; it is not evidence of semantic approval.

| Scene | Observation |
|---|---|
| Ordinary reminder | Both paths still put the no-order scope in recipient meaning. Purpose-only even phrases an internal prohibition as a directive in the rendered message. Removing the preceding draft does not remove this error. |
| Requested assurance | Purpose-only keeps assurance, but loses the actor boundary: “you won't format/delete” becomes “existing content will not be formatted/deleted.” This broadens or ambiguously globalizes a promise beyond the assistant's own behavior. Baseline abstains over unspecified timing. |

| Preliminary study | Purpose-only shares the qualified lead, but “code/data unpublished” becomes “cannot be independently verified,” stronger than supplied evidence; collector/fixture labels leak into source prose. Baseline abstains over weak evidence. |

| Today's correction | Both honor the explicit situational boundary; the purpose reason does not turn it into permanent dislike. No permanent preference is written. |

Interpretations of usefulness or timing remain tentative. In particular, absence
of a supplied due time is not proof a reminder now is bad, but the fixture lacks a
full conversation/presence history; do not grade all baseline silence as definite
failure. More messages is not automatically better. The actor/scope and source-
strength errors are reasons not to adopt the new path, not a reason to bolt another
disclaimer blacklist or universal certainty rule onto it.

## Mechanical evidence and deliberate limits

Windows and network-disabled/read-only/resource-limited Linux exercise the new
probe with fake models. They check identical inputs across paths, source-only
purpose input (no baseline leakage), same renderer contract/language, skipped
rendering on defer, literal/fidelity status remaining unproven, partial/provider
failures, no overwrite of old evidence and exact call counting. Additional cases
show a wrong family/provider failure stops after one attempt, while a matching
reported family can complete a synthetic matrix. None proves model intelligence.

The private driver uses the complete current kernel package with retained Core/
dependencies, not fresh installed-device or full production qualification. Existing
authorization, models, Core, queues, external memory links, other plugins and
production data remain untouched. FIFO/Token stay with Qoder/Enhance.

## Decision and next work

Do not automatically add an extra purpose-model call: it adds cost and does not
solve ordinary recital or actor/world-state distinctions. Do not drop all negative
statements: explicit assurance and material factual negation must survive.

Next distinguish who is acting, what kind of statement is being made (an operating
limit, a bounded promise, an observation or a world-state guarantee), and which
action a time bound governs. Test host-native/direct contribution composition as
an alternative to increasingly elaborate pre-draft schemas, with the same original
source and final correctness/authority requirements. The source-only result does
not justify weakening policy or delivering unreviewed text. Any replacement must
connect the full host/retained memory/agenda/outcome/learning loop and preserve
privacy, forgetting, migration/rollback, portability and production safety.

The long-lived objective is unchanged and uncompleted; no main merge, release,
deployment, claimed ten-clean-cycle acceptance or production restart follows.
