# ADR 0280 — Keep factual support and communication fit distinct in one call

Date: 2026-10-29. Status: development candidate; qualification pending.

## Evidence and limits

The existing final reviewer already asked about facts and recipient value. An
isolated real trial nevertheless approved a dense unsolicited benchmark account
by justifying factual fidelity and subject relevance. The communication context
was present; adding another copy of the instruction or a reviewer would not
address that conflation.

Two isolated comparisons retained the original generated text and actual model
responses. A two-dimension assessment found its reported facts supported while
its unsolicited-chat form conflicted with the supplied communication context.
A consistent synthetic request for a detailed analysis made that same text fit.
A human-authored shorter diagnostic also fit. These are limited hypothesis
evidence: configured provider routes differed, the first detail control was
internally inconsistent and was rejected as an invalid control, and none of
these is a fresh autonomous authoring or recipient-satisfaction pass.

## Decision

Replace the output contract of the existing final discovery assessment for new
`boundaries-and-source-v2` interpretations. Keep one model call with the existing
Core model, fallback, timeout and operation lifecycle. Ask separately for factual
support and actual communication fit, with grounded explanations and supplied
recipient evidence. No extra judge, vote, topic-specific policy, word quota or
compulsory opinion. Useful depth remains eligible when the actual need calls for
it; topic match alone does not establish fit. Unknown interests are not dislikes.

Retain both dimensions in the existing protected review record. Derive the
existing lifecycle verdict without interpreting prose: an explicit unsupported
fact or communication conflict gives `unsupported`; otherwise a material
uncertainty stays `uncertain`; only `supported` plus `fits` gives `supported`.
Keep exact reasons, without truncation. Validate retained findings against those
same dimensions so a stored joint verdict cannot detach from its assessment.
The existing one-correction path receives the negative findings; there is no new
retry loop. A judgment never grants sending, memory, task or execution authority.

## Persistence and recovery

The interpretation start already persists its discovery review contract. New
starts select v2; recognize both v1 and v2 when reconstructing prior records.
Both retain the existing required-meaning boundary assessment. Only the v2
context selects `factual-support-and-communication-fit-v1` for final review.
Old v1 prompts and single-verdict parsing remain unchanged. Protected-purpose
reviews are unchanged. An old or pending operation is not silently reinterpreted,
recalled, inferred again or granted a longer lifetime under the new default.

## Qualification required

Cover all fact/fit combinations, missing/invalid dimensions, retained-verdict
contradiction, old prompt/parser recovery and refusal of a legacy one-dimensional
response for a new review. Exercise actual encrypted interpretation/expression
records across the default change, cold completed recovery without inference,
negative review with at most one correction, and unchanged model-call counts.
Then use the current installed Core registry/SDK and full portable suite before
new real complete-chain samples. A green structural result is not natural
conversation, independent factual verification, fleet or production acceptance.

## Development qualification and remaining authoring issue

The pure dimensions, retained consistency and old/new parsing controls pass.
Actual encrypted v1 interpretation records generated under the previous default
resume under the v2 default without a new model call. Controlled discovery
authoring, configuration, one correction and source history pass, including the
desktop component test. Actual current Core continuity passes. Its source-depth
fixture initially failed because a controlled-response helper imported a shadow
test kernel; extracting a dependency-free fixture corrected that test failure.
The current Core chain then passes with an explicit assertion that its final
request uses the new facts/fit contract, rather than silently using a legacy path.

Full retained assessment reasons may reach 1500 characters, while the existing
local edit binder accepted only 500. Align its diagnostic-input bound to 1500,
without truncation, and test a longer reason plus refusal beyond the bound.
The earlier single-verdict parser still keeps its original 500-character finding
limit; no legacy review is reinterpreted or given new authority by this change.
The complete initial-candidate portable run and later bound alignment have
separate qualification scopes; neither is fresh real-model quality acceptance.

Global fit correction is still open. The existing exact-span editor intentionally
keeps opening, structure and depth unchanged. It is appropriate for a localized
unsupported claim; it cannot be assumed to fix a message whose whole presentation
is wrong for the situation. Validate a source-led revision within the existing
one-correction budget before claiming that detecting a form mismatch produces a
useful share. Preserve required meaning and source attribution, and re-review
the complete revised text. Do not replace this open work with more judges or
count abstention as a successful quality round.
