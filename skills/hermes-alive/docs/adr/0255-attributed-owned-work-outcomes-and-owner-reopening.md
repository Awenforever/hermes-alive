# ADR 0255: Attributed work outcomes and owner correction

First execution is only part of a useful agenda lifecycle. A separate default-off
`manage_core_work_outcomes` guided option lets Alive assess its own terminal Core
work against retained original intent and actual bounded records, including an
already-admitted independent inspection. It requires original-source retention,
Core record review and explicit owner management. Old grants do not expand.

The model judges achieved, partial, blocked, ongoing or cannot_assess. A complete
judgment must cite supplied complete evidence, preserve temporal constraints and
never equate Core completion with goal attainment. Agent statements may be text
deliverables, but are not proof of external effects. Pending independent reads
must settle first; changed sources, owner policy or item versions fence admission.
Other outcomes retain the item and an attributed recommendation. This grants no
new execution, retry, scheduler, sender or delivery FIFO.

An admitted closure has its own authority type, protected receipt, exact prior
transition and historical owner grant. It is never labeled an owner completion
report. Replay verifies that same admission without requiring expired private
model prose. A later explicit owner correction can reopen completed/dismissed
items. Old work's original item version cannot automatically close that reopened
item. Unsigned or reused closure receipts must fail.

Assessment bodies remain private, for at most seven days or the earlier original
source/item expiry. Read availability follows the original source; journal events
contain references and provenance rather than raw goals or reasons. General
source-dependent erasure, continued multi-step work, revisions/dependencies and
four-platform production lifecycle remain separate requirements. Controlled actual-Core and bounded real-model semantic qualifications are
recorded in the development plan; they are not final production acceptance.

Exact later owner work instructions are read from the authenticated owned Core
definition through at most three 4096-character pages. They are distinct from
the initial interpreted agenda and from worker statements. Missing/truncated
owner work context prevents closure; later restrictions must not disappear just
because the default historical review window was shorter. Closure admissions
have a five-minute effect window and recover without re-inference only while
source, policy and prior agenda version still match. Project in journal order.

A real outcome counterexample exposed a misleading early-error-only view: later
successful writes/reads existed but had exhausted the default review body window.
Outcome assessment now fills known owned message bodies through the existing Core
evidence reader, with a combined 16384-character budget and at most 4096 per
message. It preserves chronology, partial/omitted bodies and segment boundaries.
Missing from this bounded view never means globally absent; incomplete bodies
cannot be cited to authorize closure. This is evidence acquisition, not an error
keyword patch or permission to retry work.

The bounded hydration belongs to CoreWorkEvidence.window so other qualified
readers can reuse it; existing default review windows are unchanged. Inspection
bodies receive budget before older producer records. Omitted-body metadata keeps
its kind, timestamp and fingerprint, so absence is visible and changes invalidate
old judgments. Do not also inject a duplicate older truncated inspection body.

The new outcome grant also explicitly covers bounded matching tool requests, so
a result can be tied to its actual target/parameters instead of assuming that a
read concerned the intended file. CoreWorkEvidence.window defaults to omitting
arguments; only this separately guided reader opts in. A request is an attempt,
never proof of success, and cannot alone authorize closure. None of these raw
requests/results are copied into the Alive journal.

Invalid outcome JSON or unsupported evidence is isolated to that item's proposal:
keep it open, retain only signed rejection metadata, do not stop the whole host
or retry the physical work. Repeated preparation in the same cycle does not
re-infer that rejected basis. Harmless additional model fields are ignored;
unknown action meaning is never guessed. Authority loss still interrupts normally.

## Qualification scope

Actual-Core tests cover positive/partial decisions, invalid support, pause during
inference, crash between admission and effect, cold replay, owner reopening,
complete later instructions and large/incorrect results. Invalid proposals are
also tested in the actual continuous host loop. Real inherited main/worker/Native
execution and a later status query now preserve the finite-goal/no-close pair;
three real-model capture replays exercise the evidence counterexamples. Valid
responses remain equivalent after protocol-error isolation. Four-platform Git
consumer lifecycle, complete source-dependent erasure, general continued work
and production acceptance remain unproven.
