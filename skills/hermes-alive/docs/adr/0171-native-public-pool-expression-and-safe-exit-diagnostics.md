# ADR0171 — Exercise the collected pool through expression, retain failures

Date: 2026-10-18. Status: implemented and exercised in isolation; not deployed.

## Product evidence, not another review layer

ADR0170 preserves observations before legacy interest gates. The next question
is whether the existing composed decision/expression path uses such material
with explicit recipient memory, rather than only formatting a preselected item.
The native expression probe now accepts the same bounded public-material pool
as the interest probe, with an explicitly selected synthetic profile. It admits
the whole supplied pool through the real private ingestor, not a favored item.
Original single-item input remains usable. Resume requires the exact original
evidence and selected profile; it never substitutes another owner's journal.
Material IDs are unique, links and text are bounded, priority hints are finite
unit values, and no model, route or execution permissions come from these inputs.

## Actual runs and contradictory outcomes

The public pool contains the same 18 operator-retained NASA/Bilibili/Sspai
observations from ADR0170. Two synthetic interests concern practical e-paper/
everyday technology and astronomy respectively. They are not the owner's private
interests or distributed onboarding defaults, and no private chat is read.

Native interest r3 uses the unchanged configured primary/backup host projection.
Three logical attempts complete baseline abstention and an interest-A result
with two Sspai candidates, then fail during corrected-B. Baseline completion is
actually attributed to configured official DeepSeek backup; interest-A completes
on USTC DeepSeek. Both completed phases reopen without inference. This supports
interest-sensitive choice and an observed host route change, not complete
preference correction/withdrawal or a stable model service. The failed third
attempt has no completion diagnostics; do not invent its provider status.

Pooled expression r2 explicitly selects the already configured official backup
only inside the isolated projection. One logical attempt fails NativeCompletionError
with no observed API terminal. This contradicts blaming the earlier shape only
on Qwen. It does not identify the underlying cause, and no partial final text
becomes a usable candidate. Production model/fallback configuration is unchanged.

After adding safe diagnostics, a separate pooled expression r3 completes nine
actual logical calls: official DeepSeek interpretation/selection/rendering and
six Qwen3.8-reasoner fact/purpose/semantic/final reviews. All 18 supplied materials
are admitted; the existing runtime selects the e-paper source over the weaker
second candidate. Final source verdict is supported, semantic disposition is
shadow_eligible, and exact reopen makes zero inference calls. There is no route,
authorization, attempt, dispatch or send. This is a composed shadow quality path,
not a real delivery/feedback loop or one of ten accepted full-channel rounds.

Manual inspection finds a faithful but stiff preview-level pointer: repeated
source attribution, a URL-looking link label and a detached verification caveat.
Source title/link and uncertainty remain intact, but recipient usefulness and
naturalness are not established by the model verdict. Sspai's e-paper RSS snippet
is largely community boilerplate; the HRV snippet is a short concluding sentiment.
Two selected previews do not establish detailed article knowledge. Do not fix
this by inventing richer content or banning these particular phrases/sources.

## Bounded diagnostics without weakening completion

Native completion failure diagnostics now expose only a known Core exit-class
prefix, bounded integer token counters, whether an error field exists, and the
request's output-token/time limits. Unknown exit classes become other; any
parenthesized provider/exception detail is omitted. Booleans, negative or excessive
counter values do not become usage counts. Raw failed output, reasoning, exception
messages, keys, provider labels and private paths remain undisclosed.

These fields do not change finish validation. Started-only, truncated, changed,
foreign, stale or incomplete turns remain rejected. The instrumented successful
run does not retroactively explain earlier failures: output budget, service errors
and Core exits are still hypotheses unless a failing run supplies that evidence.
Do not increase budgets, reinterpret partial text or repeatedly resample the same
case merely to make it pass. Local native-completion and real-child protocol
tests pass, including secret-bearing exit details and invalid counter controls.
Complete current-tree portable verification remains pending at this record.

All runs terminate with no pending workers or external effects. Temporary model
projections are removed only after their owned worker/container is terminal.
Thirteen logical attempts in this series include the failed calls; physical HTTP
attempts/fallback retries are not fully metered by that number. Source/decision
records remain private artifacts, not public release payloads or user memories.

## Finite next work

Continue the existing useful discovery/decision/expression/feedback loop. Preserve
this pool as a holdout, not a perpetual test treadmill. Improve depth selectively:
when a substantive contribution needs original content, use a bounded authorized
host read rather than extrapolating from a teaser. A concise accurately attributed
resource pointer may still be appropriate without reading every article/video.
Do not reuse an unrestricted URL fetcher without validating its network boundary.

Improve natural expression by treating meaning units as meanings, not mandatory
paragraphs or repeated labels; retain material uncertainty and exact links. Compare
fresh messages and retained meaning, not only model approval. Real attributed
feedback, noisy-conversation extraction, sustained usefulness, external memory,
fresh lifecycle/migration/rollback and production acceptance remain unqualified.
No new judge, memory service, model registry or channel FIFO is introduced here.
