# ADR 0238 — Exact adapter-reported share lookup before quoted feedback

Status: candidate; no automatic feedback ingress or inbound body capture enabled.
Date: 2026-10-26.

## Evidence and problem

Two real-model controlled experiments do not justify another broad writing rule.
Additional original PDF/site material increased numerical inventories; worked
examples improved one science account but not a robotics account. Neither arm
is a new useful content round or a basis for expanding runtime read budgets.
The missing longitudinal path is actual attributed response to prior sharing.
Current Core admission snapshots omit quote metadata and bot identity; existing
scoped ephemeral metadata experiments can bridge those fields, but they are not
runtime feedback capture. On current supported Core, the real Gateway admission
and routed-profile probes now pass after initializing Core's known read-only Git
version identity before their effect guard. The guard remains unchanged.

Prepared share context and an adapter's successful return do not establish that
a person received/read a whole message, nor the complete IDs of split bubbles.
The retained adapter observation does contain a keyed reference to its reported
message ID and launch route. Guessing the newest share would lose attribution.

## Decision

Add a read-only internal ShareContinuityStore lookup for an exact reported ID in
the canonical owner/profile/transport/chat/thread/session. It compares the keyed
route+ID reference only against authenticated successful adapter observations
for retained share headers. Scan at most128 owner headers; no match or multiple
candidates returns unavailable before body decryption. It then uses the existing
exact-reference read to enforce original scope, retention, expiry and forgetting.
Errors, uncertain sends, foreign scope, insufficient clearance and altered
observation signatures cannot resolve a target. No plaintext ID or new record is
written; no expiry, authority or delivery state is renewed.

The result explicitly remains an adapter-report match, not canonical quote proof,
remote delivery, a complete bubble inventory or permission to record feedback.
No model tool, new queue, Core patch or plugin dependency is introduced. This is
usable target-location groundwork, not completed user-feedback learning.

## Qualification and next integration

Exercise actual Core-backed share preparation/standard adapter return/reopen and
lookup, including failed/uncertain returns, unknown IDs, malformed IDs, public and
foreign scopes, altered signatures, structural ambiguity, expiration and forgetting.
Check no journal mutation and no body decryption on pre-admission refusals.
Preserve existing continuation and source-reader regressions.

Next, bind actual admitted human-owner quote metadata to this lookup, preserve
ambiguity and establish quote corroboration without fabricating delivery receipts.
Obtain separate explicit inbound retention/model-processing choices in onboarding;
outbound retention or profile reading is not such a grant. Retain exact bounded
paired wording as retractable context, without assigning a permanent interest or
sentiment from one reply. Do not enable raw private-history collection or weaken
legacy outcome/delivery evidence to make this slice pass. Split/media IDs that
are absent from the adapter report require their actual owning transport's
receipts; never guess an ID or require Enhance to be installed everywhere.
