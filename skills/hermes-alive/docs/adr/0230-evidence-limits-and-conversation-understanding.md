# ADR0230 — Collection limits are not negative facts about the world

Date: 2026-10-25 (Asia/Shanghai).
Status: structurally qualified; actual main-model overclaim remains unresolved.

## Additional qualification — source relationships in a follow-up

A later real official-model trial revised an overlong, overbroad video-model
draft into a source-supported explanation of chaining generated clips. The
share cited a cloud documentation page about one model version. The first
ordinary follow-up recommended two demos from an additionally read repository
about a different version, and assigned both clips functions that the retained
README did not establish. The second reply acknowledged the version difference
and the absence of video inspection, but that did not repair the first answer.
The complete round receives no quality credit.

The continuity reader now reports whether each retained public resource is
actually linked in the exact share. This is a lexical citation relationship,
not semantic entailment, authenticity or authority. An unlinked resource may
still be useful; it cannot silently inherit the cited resource's object,
version or observed result. The field is computed from the protected original
share and retained URL, preserved through full context, budgeted catalogs and
source-reading tools. It does not rewrite the stored source or widen retrieval.

Conversation guidance retains the actual share as the focus and separates a
resource's description from evidence of what uninspected content shows. No
product names, domains, demo keywords or versions are used as a filter. Verify
the field through actual Core source reads and cold reopening, then qualify
natural replies using real models. A passing metadata check does not settle
the semantic boundary or advance the fresh sharing streak.

Fresh real-source trials establish two distinct product problems. One scientific
share was understandable but did not clearly convey what made its central
relationship interesting. A different technical share explained a concrete
failure mechanism, yet the ordinary main-model followup converted missing
replication evidence in the available material into an assertion that no
independent replication existed. Factual collection and natural continuation
must preserve the scope of knowledge, not merely reproduce the topic.

## Narrow implementation

Keep the authenticated share, sources, collector metadata and delivery state
unchanged. The conversation projection exposes what was actually collected:
the retained excerpt and its reported reading scope and representation. Negative
collector proof flags remain in diagnostics rather than entering dialogue as
apparently global negative facts. Explicitly distinguish an evidence limit from
absence of independent replication or later results. Faithful explanation in
ordinary words is also different from adding an unsupported factual assertion.
This does not establish verification, make sources authoritative, or authorize
new reads, model calls, memory collection or delivery.

Composition uses mathematical notation readable in ordinary chat without
assuming a LaTeX renderer. Values, units, qualifications and protected literals
retain their original obligations. No post-generation formula regex or silent
rewriting is introduced.

## What is not adopted

A controlled four-call comparison on two fixed public materials changed only
the writing task framing. The shorter conversational prompt could still list
scores, exaggerate comparative capability and misstate a model-name change.
That experiment does not justify replacing the production writing prompt or
claiming its length is the root cause. Nor should an agent's internal research
assignment be restored as the recipient's goal to make a story sound purposeful.

The point worth sharing should become apparent through a supported explanation,
relationship, distinction or possibility. It need not become a required benefits
paragraph, application claim, technical breakthrough, personal feeling or
criticism. No topic-specific style blacklist or fixed article template follows.

## Separate memory work

An offline actual-Core probe with synthetic messages found that
`SessionStore.load_transcript` requests durable replay repair; it is not a pure
advisory read. `SessionDB.get_messages` supports an exact-session bounded tail,
but its row bound does not bound body size, and a `user` role can also contain
generated notifications and quoted text. Therefore no private-history reader is
enabled by this change. Curated-profile consent must not silently expand into
dialogue processing or permanent preference learning. The native feedback path
still needs an explicit, scoped product integration; component APIs alone do not
establish ordinary daily learning.

## Verification boundary

Check actual Core context injection, exact original share, preserved diagnostic
records, erased/foreign/session-reset refusal and model-visible evidence scope.
Replay the original public continuation through the actual main model before
claiming behavioral improvement. Deterministic projection tests prove scope
handling, not that a model cannot overclaim. Real content usefulness, ten fresh
full-chain rounds, fleet lifecycle and production acceptance remain separate.

## Qualification update, 2026-10-25

The actual supported-Core continuity/setup/control/authoring focus passes, as
does the complete98 portable suite. Two actual-model notation cases produce
plain-text arithmetic for semantic content while preserving an explicitly
protected LaTeX literal exactly. These checks do not establish article quality.

A fixed-share before/after main-model comparison still fails semantically. The
new response correctly says missing material is not proof of nonexistence, then
ends with a stronger negative conclusion not justified by that material. Keep
the clearer evidence projection, but do not report this as a complete repair or
promote the correct disclaimer into proof that the whole reply is faithful.

## Qualification update, 2026-11-25

An ordinary reply joined the low-temperature result from one preparation
method to a durability measurement from a second method. The active provider
request contained the original passage with the correct attribution. Later
turns held the earlier source page as a scoped reference, which preserved the
deletion boundary. Both stages matter when diagnosing the reply.

Two retained-input comparisons reopened the same isolated Core session and
used its actual reference tool. Splitting a page into exact source paragraphs
left material response-quality problems. Supplying the exact claim-to-source
witnesses shortened one open-ended reply, which then used a technical term
absent from the retained passages. Both arms answered a separate exact-link
request with a single correct link. These results leave evidence presentation
as a development hypothesis and provide no qualification credit.

Core 0.23.3 exposes a final-output transform. Its documented stream hold
applies to the whole profile, and transformations without that hold run
after streaming may already have exposed the response. Keep ordinary
streaming and Core ownership on this path. A future live verification design
should prove turn-scoped validation, preserve durable conversation history
and evidence erasure, and measure latency on unrelated turns as well.

## Scope review and repair, 2026-11-26

The ordinary reply review worked better when it examined only consequential
claims and required exact spans from the answer and the evidence. It found
results assigned to another experimental setup and causal language that went
beyond the available material. Accurate controls retained the original
conditions and passed. The combined format and fact review had accepted
explanatory paragraphs in a link-only turn, so format remains its own
requirement.

Two retained replies went through one evidence-constrained repair and one
blind recheck. Both repairs answered in a single sentence and kept
experimental scope and results separate. These were isolated trials using
existing evidence, and neither result entered a live conversation.

Core 0.23.4 retains the same profile-wide stream hold and finalization
behavior as 0.23.3. The upstream before-final proposal remains open.
Any future live integration needs a turn-specific admission captured before
output can stream, current evidence and consent checked again at delivery,
and a bounded attempt to repair the candidate. Rejected drafts and repair
instructions must stay out of the visible reply, saved conversation and
compression input. Unrelated turns keep their ordinary delivery path.

## Keep source claims with their entity and phase, 2026-11-26

The Mercury follow-up treated the spacecraft's launch configuration as a
current relationship. The relevant retained passage described launch. The
reply could answer that the orbiters' separation was still planned without
asserting what else remained attached. A retained-input trial kept that
distinction and passed a blind recheck. The same instruction also preserved
the subject and conditions of a previously misattributed ceramic result.

The native context experiment added this distinction to the continuation
prompt and the scoped source-reader description. Its first version displaced
the source catalog under Core's 2,000-character hook budget. A shorter
version restored the exact share and source indices at that cap and passed
the Core retrieval tests. A cold replay of the same Mercury share on the
shorter version still asserted the launch configuration as current. The
prompt change was removed from the candidate. Source retention and routing
continue on the previously qualified implementation.

A fresh snow-cover run reached an actual model continuation and correctly
separated historical observation from scenario projection. The first answer
added a separate explanation to a one-sentence request. Keep fact grounding
and the shape of the full reply as independent acceptance requirements.

In a disposable Core profile, an ordinary model turn produced an unsupported
claim about the transfer module. The held transform received the final draft
and exact source pages, made one bounded model call, and replaced the answer.
Core emitted no nonempty text deltas or interim message and returned the
replacement in the conversation. An earlier callback failure gave Core's
controlled withheld response. These are separate controlled outcomes.
Evidence capture in this experiment was restricted to the particular
replayed session and turn. A second held native run reopened its SQLite
transcript and found the final replacement, with the rejected draft absent.
It also showed a remaining quality requirement: the replacement repeated
the initial burn duration alongside a later correction. Validate the
replacement itself against the relevant phase and source revision.

The existing Core hold is profile-wide. A live design needs a host-owned
decision before the first possible emission, a bounded review deadline, an
authorized view of the relevant turn and current references, and a safe
result on timeout. Revalidate references before delivery, prove that neither
discarded text nor ephemeral repair instructions enter durable history or
compression, and verify that an unrelated turn can still stream. Preserve
the upstream hook boundary described in [Core issue #101910](https://github.com/NousResearch/hermes-agent/issues/101910).
