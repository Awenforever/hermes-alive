# ADR0221 — Native content recovery with frozen candidate scope

Date: 2026-10-24 (Asia/Shanghai), Codex.
Status: implemented; qualification in progress.

Consume ADR0220's authenticated bounded eligibility in the ordinary configured
native host, rather than merely exposing another reader. Observe listings before
the existing wait check. When cognition is needed, freeze source-reading choice
before model selection and exclude held primary URLs. Empty eligible material
requires neither a reading model nor a candidate model. Preserve source records
and related evidence; a rejected expression is not a user preference or bad fact.

Fresh planning retains a versioned material scope with full evidence IDs and a
separate eligible-primary set. The latter constrains anchors, not grounding.
Deferred source IDs audit the initial decision without becoming current fact
dependencies of another good message. Replay uses the original operation's scope,
not today's expiry, and verifies the same retained planning input. A hold expiring
must not shorten the grounding lifetime of a message waiting in Enhance's FIFO.

All-held output is content_deferred, not a conclusion that nothing is worthwhile.
Reconsideration keys include current hold identity/deadline as well as observed
listings. Ordinary silence can still reuse its original derived parameters and
candidate scope. New owner input, material, configuration/policy or expiry wakes
the existing path; reading does not extend the original deadline.
The wait fingerprint canonicalizes evidence order inside the same bounded fair
window: advancing the scan cursor alone is not new evidence. Different window
membership, content and retention remain wake conditions. The original ordered
candidate pool is still bound and validated independently.

Continuous recovery is opt-in from a preparation that actually consumes holds.
Continue a negative review only with its existing qualified witness, configured
bounded window and unexpired original review-time boundary. Keep the negative
outcome as negative. Default direct hosts, pending/unknown work, unavailable
repair and other attention remain conservative. There is no physical retry,
delivery claim, new transport queue, permission or model configuration change.

Synthetic native recovery tests exercise all-held, alternative source, retained
wait/reconstruction and expiry using the actual kernel with fake public IO/model
responses. They are component integration evidence, not real model quality,
Core daemon restart, fresh consumer installation or fleet acceptance. Quality
remains 0/10 and production is unchanged.
