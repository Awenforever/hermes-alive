# ADR 0254: Guided first autonomous Core work

An existing, explicitly owner-assigned agenda item may begin on a later Native
wake without pretending that the owner sent a new execute message. This is a
separate default-off `autonomous_core_work` guided option. Existing grants do not
expand. It requires Core background work, retained original intake and explicit
Core request retention, plus selected automatic Core toolsets. Outside that scope
requires the existing owner-confirmed operation path.

The model interprets the retained original request together with its interpreted
agenda, timing and scope. It must preserve further-confirmation requirements.
Waiting reasons are private attributed evidence for subsequent cognition and owner
status; they are not tool permissions. A wake or active agenda label is not new
authority. Deleted or expired original evidence cannot be reconstructed to execute.

First execution reuses Core's job, model, scheduler, permission and tool dispatch.
The original is labeled historical in both the signed admission and Core prompt;
there is no fabricated current-turn evidence. Validate signed policy, source and
scope before admission, activation and each owned tool. Stop markers remain binding.
The stable owned admission prevents replacement/retry after uncertain, failed or
stopped work. Local Core completion is not agenda success or permission to contact.

This is first-work admission, not a second agent loop or general goal closure.
Task revision/dependencies, project context, independent result interpretation,
appropriate closure and platform lifecycle acceptance remain separate requirements.
Controlled actual-Core and real-model semantic qualification must be recorded
separately; no production or final acceptance is claimed by this design.

## Qualification boundaries

The actual-Core focus exercises later-wake write/read effects, explicit waiting,
pause despite an incorrectly enabled projection, erased original source and an
old installation without the new grant. A bounded scan passes unavailable rows;
same-cycle cursor re-entry is idempotent. The real inherited main/Native/worker
positive/wait pair uses original historical instructions and bound actual Core
read/write/readback records, with zero delivery and no automatic agenda completion.
Existing Native preparation may run multiple passes in a cycle; its total call
budget still applies. Cold automatic startup is qualified separately from a
manual post-restart step and from real-model semantic intent.

The controlled two-process startup case now passes: first-process registration
creates no work; the cold process retains session/configuration/activation/key
identity and its real startup loop admits the job on its first automatic wake.
The normal interval stays 600 seconds, with no manual Native step for admission.
Core's actual write/read effects are then observed. This is not a real-model
cold daemon or four-platform consumer qualification.
