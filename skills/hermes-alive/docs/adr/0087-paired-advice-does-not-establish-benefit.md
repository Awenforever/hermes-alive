# ADR 0087 — Paired advice experiment does not establish operational benefit

Status: prospective paired component evidence; no superiority, automatic learning
or full Alive qualification claimed.

## Prospective manipulation and controls

Three new authored public synthetic cases precede the calls: permission without
enthusiasm, an old meeting refusal whose meeting is over, and one detailed-answer
request rather than a general style preference. Opportunities have no urgency or
actual external action. The existing synthetic seed accepts axis/key/option as
keyword inputs; defaults are unchanged. These are authored observations, not
autonomous learning. Each journal/vault is cloned before either call, preserving
canonical IDs, weights, opportunities and owner context. The control reader removes
evidence_notes from serialization only. Both arms retain the current mass-semantics
label and prompt: an ablation of notes, not a historical-release comparison.

Clock as_of differs between sequential calls and is disclosed. Order alternates.
Same main model, one sample per arm, temperature .2; no statistical power,
independent utility assessor or human-gold outcome. Both arms use the actual
OpportunitySynthesizer with stable reader objects for post-call evidence checks
and prompt digest. Candidates have ActionAuthority.NONE; no selector or dispatch.
The explicit opt-in probe caps logical calls at six and async HTTP attempts at
eighteen, preserving raw synthetic responses including rejected proposals.

## Result: no demonstrated improvement

All six logical calls observe HTTP 200 at api.llm.ustc.edu.cn and report
deepseek-flash/custom:ustc. All three pairs match except notes and clock. Permission
and one-off style cases return empty candidates in both arms. Both meeting-case
raw responses propose similar optional shares with low urgency and uncertain
relevance. Qualified accepts one proposal; flattened accepts none but records one
rejection. This is not proof of a better model decision or deliberate silence.

The flattened risk explanation has 143 characters, exceeding the adapter's old
128-character cap and rejecting the whole proposal. Other reasons are shorter.
It did not fail authority or a substantive relevance test. DimensionAssessment
already preserves up to 512 characters: the narrower unexplained adapter cap was
an inconsistent representation budget. The adapter now shares that 512-character
limit, explicitly advertised in the prompt. Explanations are not truncated or
invented; 513 remains rejected and numeric/source/identity/authority bounds remain.
Regressions test exact preservation at 129/512 and rejection at 513.

Probe reporting distinguishes model_empty, all_rejected, partial and proposed,
with model proposal count. Fake regressions exercise empty and fully rejected
responses so zero accepted drafts cannot masquerade as silence. No semantic weight
change or permission/meeting keyword rule is added. The original report/receipt
is unchanged; accepting its raw text under a revised contract is not retroactive
model-run success. Final code has not been run in another live experiment.

Two pairs are uninformative about qualification use because both choose silence;
the third shows no clear semantic improvement before validation. Weak opportunities
and absent explicit interest limit sensitivity. Next use fresh meaningful
opportunities with matched explicit baseline context, positive/negative controls
and repeated assessment. Do not force communication, cherry-pick a winning sample
or change expected constraints after seeing outputs.

## Design audit: scenario labels contaminated the control

The retained primary inputs expose semantic case names through subject/evidence
IDs and example URLs, including `meeting-not-permanent-ban`. That leaks intended
qualification into the flattened arm, even though all matched-input checks pass.
This is an additional serious confound: paired parity alone does not prove clean
manipulation. No claim is made that label leakage caused any particular output,
but the experiment cannot distinguish that possibility from real reasoning.

The final probe uses opaque hashed subject IDs and URLs. A fake regression checks
that none of the three scenario-label strings occurs anywhere in a model input.
Report/corpus labels remain outside model messages for traceability. Source titles,
ordinary target labels and the deliberately manipulated rationale remain visible;
this is label blinding, not removal of the actual scenario's meaning. No live
experiment has yet tested the label-blinded revision.

Audit other evaluation probes before semantic qualification: older feedback fixtures
and independent review case IDs also contain authored semantic labels. Their
observations and reported responses remain real, but do not establish blind semantic
performance. Do not retroactively erase, relabel or count these runs as held-out
validation. Next use fresh meaningful, blinded, controlled cases; the review/audit
finding changes the next action instead of just accumulating more calls.
