# ADR0237 — Separate required meaning boundaries from source judgment

2026-10-26, Codex. Status: candidate; qualification pending.

## Evidence and decision

A fresh real-model discovery cycle reached a source-authored candidate with only
its canonical link as required meaning. The source-aware semantic reviewer marked
an unsupported addition without locating the claim; the final source/value
reviewer supported the same candidate. The pipeline safely withheld the message.
Inspection disproved an initial generic-review-routing suspicion: the proper
group-source contract was present. Neither model verdict establishes ground truth.

Both stages currently judge source entailment, with different response contracts.
An opaque boolean disagreement cannot support accountable local correction. Do
not resolve it by voting, silently discarding a negative, adding more judges,
keywords for one story or compulsory disclaimers. Assign responsibilities instead.

Fresh source-led v2/v3 interpretation starts record boundaries-and-source-v1.
The first review checks only explicitly required meaning atoms, their essential
relations/negation/uncertainty, protected literals and speech act. Its actual
model request contains meaning and candidate, not the original source bundle.
It does not assess factual additions beyond those required atoms. The signed
semantic receipt records required-boundaries-v1; the compatibility envelope's
added_claims_detected=false is NOT a factual-support verdict. A supplied opaque
true addition flag is not admissible under this contract. A valid negative
boundary/atom assessment remains a rejection. No silent positive conversion.

The existing final source/value reviewer alone assesses the complete discovery
message against original sources, actual scope, explicit context and current
review clock. It must name concrete offending wording, evidence/missing material
qualification or content/value mismatch when negative. Its original bounded
local-correction slot remains; no additional model ladder or perpetual rewrite.
A positive boundary review cannot authorize a share without current final-source
proof. Final negative/unknown, missing source, privacy/expiry/forgetting and all
independent route/action/delegation gates still prevent execution.

## Historical and cross-purpose contracts

The scope is derived from the authenticated original interpretation start, not a
model parameter or current default. Old starts/bundles keep their original method
and evidence, including old source-aware semantic judgments. Recovery reuses the
original parser/prompt according to that method. Source-led v1 is historical.
Protected-purpose communications retain their full original meaning contract;
this decision does not make warnings, deadlines or explicit user instructions
into free source-authored prose. Reviews remain advisory, never truth or authority.

The expression review reader derives this scope from the current selected
intent. A correctly signed receipt with a removed/substituted scope or a source
addition flag cannot masquerade as the original required-boundary assessment.
No Core, model configuration, private history, channel FIFO or production change.

## Qualification required

Use encrypted actual APIs and current Core: new starts with source facts outside
a required URL, valid negative atoms, malformed and opaque source flags, one
protocol repair and cold recovery, current final-source mandatory denial, original
keys/state, historical contracts and strict protected-purpose meaning. Then use
actual models on public fresh material and inspect original outputs. A positive
component result or safe silence does not advance ten useful quality rounds.

## r98 first qualification failure

The new fixture incorrectly used the generic SemanticReviewStore to read a
source-authored opportunity expression. That base store does not support this
selection format; the actual runtime uses OpportunityExpressionStore. Keep the
failed candidate and output. Use the actual runtime reader for both legitimate
and correctly signed scope-mutation checks; do not weaken a validation to admit
a new store format. No model or channel call occurred in the failed fixture.
