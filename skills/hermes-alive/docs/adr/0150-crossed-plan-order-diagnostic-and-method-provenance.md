# ADR 0150 — Test contract/order hypotheses before changing cognition

Date: 2026-10-16. Status: diagnostic evidence and interpreter audit improvement;
no winning expression strategy, runtime prompt replacement or production activation.

## Question and design

The complete chain still promotes operating limits to recipient-facing meaning.
Do not delete a disclaimer or claim that shortening a prompt fixes intelligence.
Cross two factors on six fresh synthetic scenes: current versus compact contract,
and requested draft-first versus communication-plan-first **output order**. One
generation per cell, rotated execution positions, no best-of-N and no implicit
provider retry. Each case supplies the same time-anchored input to all four arms.
Expected outcomes and arm names are not sent to the model.

Scenes cover an ordinary scoped reminder, explicitly requested assurance, activity
eligibility/booking, a limited preliminary study, temporary exam silence and a
tool-update source containing an embedded malicious instruction. These are manual
synthetic prompt fixtures, not authenticated installed host inputs. The diagnostic
creates no selected intent, channel queue, send, tool action or learning record.
Its use of the actual candidate parser proves structure only, never source truth.

Requested JSON key order is a proxy, not observation or control of hidden reasoning.
Record actual order rather than silently rearranging it. The compact contract
changes wording and framing as well as length; do not infer a pure length effect.
Same-family outputs, one sample per cell and no full rendered/delivered chain are
not independent review, statistical qualification or longitudinal utility.

## Preserve the defective first protocol

`model-only-plan-order-20261016-r1/results/report.json` under the retained isolated
root records 24 logical/24 observed HTTP starts. Two experimental defects were
found, not hidden or attributed exclusively to the model:

1. Compact instructions did not give an equally explicit full candidate object;
   many outputs omitted the mandatory action kind. Ten cells contain structurally
   rejected candidates, four have admitted structural candidates and ten abstain.
   An earlier fake-model test supplied the field itself and did not catch the weak
   instruction. Do not infer poorer semantic ability solely from this imbalance.
2. The fixture builder assigned a 45-minute deadline to both reminder scenes,
   although only the first request specifies time. The second scene's model saw
   that synthetic target; surfaced timing cannot fairly be blamed solely on it.

Protocol 2 gives every arm the same explicit field/shape example and only attaches
the 45-minute target to the actual timed request. New tests verify both conditions.
It retains the original report, does not repair malformed model JSON and repeats
all 24 cells rather than selectively replacing failures. Because the baseline now
has the shared schema example, this is not a byte-exact production-prompt replay.

The first outputs were displayed sorted by opaque ID without their arm mapping,
then inspected before mapping lookup. This was the implementing agent, not an
independent or double-blind judge. IDs repeat across runs, so second-run inspection
is expressly not blind. Raw reports retain both mapping and exact prompts.

## Interpreter method provenance added, not a new decision gate

Experiments highlight that a retained result needs its actual producer method,
not a guessed attribution to whatever prompt the code currently contains.
`opportunity.synthesis_started.interpreter_method` now records the selected
producer protocol, requested model and SHA-256 of the exact system prompt passed
at Alive's model-call boundary, before provider access. The prompt is composed
once and the same value is passed to the call. No private user prompt is copied.

No-material starts are explicitly system_no_material, with no model prompt hash
or requested model claim. Actual model identity remains the separate completion
receipt, including any configured fallback. A requested model is not proof of
the route used; a boundary hash is not a wire-level attestation. Old records with
no method metadata stay unknown, not retroactively labelled using current code.
Recovery still revalidates original evidence/ownership and never infers authority
from this audit metadata. Runtime prompt content and model configuration are not
changed by extracting the existing prompt expression into one local value.

Windows fixtures verify empty/no-spend provenance, exact call-boundary hash and
requested-model binding through legacy/v1/v2/one-correction composed paths.
Windows and offline Linux diagnostic tests verify 24 attempts, failure counting,
raw invalid output retention, paired input equality, order observation, no expected
answer leakage and refusal to overwrite an existing result directory. Full-current
package offline regression covers the new method and thirteen neighboring scripts;
fourteen scripts terminate successfully, not fresh installation or full CI.

## Next architecture decision remains open

Do not adopt either candidate just because it is simpler or more talkative. A real
purpose-only interpretation stage must derive needs from original source/current
owner context **without an already proposed draft or self-declared candidate goal**,
then separately compose and assess expression. This is different from moving a
JSON field before text. Qualify explicit assurance versus operating scope, factual
conditions, timing relation (reminder window versus underlying-task deadline),
unknown affiliation and warranted silence on new paired cases. Preserve action
authority outside any model-derived purpose and avoid another permanent preference
or confirmation requirement for each tentative interpretation.

Continue the full autonomous host, layered/external memory, sustained agenda,
feedback/reflection, privacy/forgetting, migration/rollback, portable lifecycle and
production acceptance objective. This turn supplies evidence and auditability,
not a completed intelligent kernel. Enhance/FIFO/Token remain Qoder's ownership;
no Core, production, wmw, other-plugin, proxy or Tailscale change is made.
