# ADR 0139 — Actual next-cycle decisions with registered intent context

Status: limited diagnostic evidence; no production qualification.
Date: 2026-10-15.

## Question and method

Does a configured model use registered-intent/outcome context without inventing
delivery history, blanket silence, or a new reason to repeat unchanged material?

Four distinct synthetic journals retain a seeded initial draft and registered
attempt. Two also contain authenticated synthetic transport outcome fixtures.
All receive the same explicit synthetic interest in practical clothing repair,
no unchanged repeats, and openness to genuinely different techniques/corrections.
Only the next opportunity interpretation uses the actual configured model.
No private conversation, real transport or live user feedback is used.

The finite run completed four logical calls and four observed HTTP starts, all
HTTP 200 with actual model `deepseek-flash`. The runtime inherited the existing
primary/official fallback configuration without changing it. Fallback was not
exercised and is not newly qualified by this run. The job is terminal, its test
container was auto-removed, temporary model credentials were removed and verified
absent, and production start time was unchanged.

## Observations, not a parser-based semantic score

| Supplied context | Observed next interpretation |
|---|---|
| Registered pocket-repair contribution, no outcome | Abstain from repeating unchanged content; describes generation/registration, not receipt. |
| Same contribution with synthetic delivery observation | Abstain from unchanged repetition; no invented user interest or reply. |
| Same contribution with synthetic failed delivery observation | Acknowledges the recorded failure, but does not turn it into a new unchanged share/retry. |
| Registered pocket-repair contribution plus a new zipper-replacement source | Skip the old source and propose the meaningfully different method, preserving its synthetic/unverified status and source link. |

Engineering inspection found no invented conversation, prior explanation or
completed-operation claim in these outputs. This is not independent blinded
semantic review, longitudinal user benefit, or proof that the new context caused
better decisions than wording history alone: no ablation was run. Silence is not
automatically useful; the failure case does not establish recovery of an orphaned
intent or justify permanently withholding a contribution that was never delivered.
Transport settlement and useful recovery remain separate unresolved work.

Actual cumulative totals are now 132 logical calls / 145 observed HTTP starts,
with zero actual channel sends. These four samples are not ten clean production
cycles and do not qualify the complete autonomous loop.

## Reproducible diagnostic and failure visibility

`tests/probe_alive_live_action_history.py --output <empty-private-directory>` is
an explicitly invoked diagnostic, never an installation/activation step. It uses
Hermes' configured model caller and only synthetic fixtures under the chosen
output directory. It does not export credentials, choose a personal provider or
send messages. The initial actual run used the corresponding private harness;
the versioned diagnostic preserves its scenarios and adds explicit checks that
interpretation creates no additional attempts/dispatch records.

The report retains synthetic prompts and raw model output even on parse failure,
but provider exceptions are recorded by class, not message or credentials.
Failure and unassessed items are not rewritten as successful non-action. It
refuses a nonempty output directory before inference to avoid overwriting prior
evidence. Finite logical/HTTP bounds do not establish exact provider billing.

`tests/run_action_history_live_probe.py` injects a model-only fake and forbids
network IO. It checks invalid JSON remains visible, the public interpretation
error and its underlying structural error are distinguished, a synthetic secret
in a provider exception is absent, the run remains finite, no new attempt/dispatch
is created, and evidence cannot be overwritten. The first Windows invocation had
an incorrect expectation that the public exception was the leaf JSON error;
the runtime correctly wraps it. The diagnostic now retains both classes. This
test-harness correction is not a production runtime fix or actual-model pass.
The latest unit fixture passes on Windows and resource-limited, network-disabled
Linux with a retained-module read-only overlay. It is included in portable CI,
but this turn does not claim a full CI/fresh-install or lifecycle pass.

## Next

Qualify genuinely new histories and actual feedback meanings, then connect
reviewed, retractable tentative advice without converting model suggestions into
durable user authority or requiring per-message human approval. Keep unresolved
intent admission/settlement, useful longitudinal decisions, layered/external
memory, sustained agenda/adaptation, authenticated host/feedback, privacy,
portable lifecycle, migration/rollback and production acceptance in scope.
